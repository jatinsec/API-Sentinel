# API-Sentinel

A **structured API security assessment and evidence organizer**, built around a reusable
OWASP-API-Security-Top-10-based checklist. It helps a researcher record manual test cases
(expected vs. actual behavior, with evidence), and turns those records into a Markdown or JSON
report.

**API-Sentinel does not attack anything itself** — it organizes the results of manual testing you
perform yourself, against a target you're authorized to test. The repo ships a small local lab API
(`demo_api.py`) specifically so every example here is executable and reproducible, instead of
hypothetical.

## Features

- `checklist.json` — a reusable checklist covering Authentication, BOLA, BOPLA, Rate
  Limiting/Resource Consumption, BFLA, Business Logic, SSRF, Security Misconfiguration, Inventory
  Management, and Injection, each item tagged to its OWASP API Security Top 10 (2023) category.
- `sentinel.py` CLI to record test cases (`endpoint`, `expected`, `actual`, `result`, `evidence`)
  against that checklist, and to render a Markdown or JSON assessment report.
- `demo_api.py` — a minimal, intentionally-vulnerable local lab API (stdlib only, no external
  deps) with a real BOLA and a real BFLA defect, used both by the automated tests and by the
  sample assessment, so the "demonstrated impact" in this repo is something you can reproduce
  yourself in under a second.

## Installation

Python 3.10+. No third-party dependencies for the tool itself (only `pytest` for the test suite).

```bash
git clone https://github.com/jatinpatel-hacker33/API-Sentinel.git
cd API-Sentinel
pip install -r requirements-dev.txt   # only needed to run the tests
```

## Usage

### 1. List the checklist

```bash
python3 sentinel.py list-checks
```

### 2. Run the lab API and test against it

```bash
python3 demo_api.py &                 # starts on http://127.0.0.1:8765
curl -i http://127.0.0.1:8765/orders/1                                      # 401, no token
curl -i -H "Authorization: Bearer bob-token" http://127.0.0.1:8765/orders/1 # 200 — BOLA: bob reads alice's order
```

### 3. Record what you found

```bash
python3 sentinel.py record \
  --assessment my_assessment.json \
  --target "API-Sentinel demo lab API" --tester "Jatin Patidar" \
  --check-id BOLA-01 \
  --endpoint "GET /orders/1" \
  --expected "403 Forbidden for a non-owner token" \
  --actual "200 OK, full order body returned to bob-token for alice's order" \
  --result fail \
  --evidence "curl -H 'Authorization: Bearer bob-token' .../orders/1 -> HTTP/1.0 200"
```

### 4. Generate the report

```bash
python3 sentinel.py report --assessment my_assessment.json --format md --out report.md
```

A full worked example is in `samples/sample_assessment.json` → `reports/sample_report.md`
(generated by the exact commands above, see `Makefile`/`README` reproduction steps — regenerate
it yourself with `python3 sentinel.py report --assessment samples/sample_assessment.json --format md --out reports/sample_report.md`).

## Tests

```bash
pip install pytest
pytest test_sentinel.py -v
```

The test suite spins the demo API up on an ephemeral local port and reproduces both shipped
defects live (not mocked), plus unit tests for the checklist/record/report logic. 12/12 passing
as of the last run documented in this repo's commit.

## Limitations (honest)

- `demo_api.py` is a **teaching lab**, not a realistic production API — it has exactly two
  deliberate defects and nothing else; don't treat it as a general API-security training ground.
- API-Sentinel has no network/attack code of its own: it never contacts anything you don't point
  `curl`/Burp/your own script at yourself, and it never contacts a third-party API.
- The checklist is a starting point (OWASP API Top 10, 2023 edition) — it is not exhaustive for
  every API's specific business logic, and categories like Business Logic Abuse and SSRF need
  target-specific test cases you write yourself.
- Report generation is intentionally simple (one flat table + a findings section); it does not
  compute CVSS scores or deduplicate near-identical test cases.

## Ethical use

Only run `record`/test cases against APIs you are explicitly authorized to test — your own lab,
`demo_api.py`, or an in-scope bug bounty/pentest target. Never point manual testing from this
toolkit at a live third-party API without authorization.
